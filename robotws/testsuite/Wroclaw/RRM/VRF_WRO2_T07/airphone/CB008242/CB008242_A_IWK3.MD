## 1. DESCRIPTION

This test case describes the gNB behaviour when gNB-DU detects overload. The gNB-DU sets the gNB-DU overload trigger as ACTIVE in all cells with overload automatic UAC trigger configured and starts broadcast max automatic UAC configuration in SIB1 for them.

## 4. TESTING INSTRUCTIONS

### 4.1 Preconditions

-   **CB008242-A\#B1**: Preparation to User Scenario [5G_RAN_USR_RRM_23761] and there are cells with overload automatic UAC trigger configured: **triggersBitmap** is configured with Overload bit set to **1** Overload load trigger is configured
-   **CB010790-A\#3** GNB-DU Overload detection [5G_RAN_USR_RRM_23272] **actUacBarringAlarm** is set to **'true'**

### 4.2 Test Steps:

#### Step 1:

1.  gNB-DU detects overload state (see procedure from CB010790-A\#3 gNB-DU Overload detection [5G_RAN_USR_RRM_23272]).
2.  gNB-DU starts startUacBarringTimerOverload
3.  startUacBarringTimerOverload expires

#### Step 2:

1.  The gNB-DU immediately builds and broadcasts SIB1 message with the highest automatic UAC threshold in all cells with overload automatic UAC trigger configured. Multiple UEs established RRC connection with gNB.
2.  uacUpdateTimer is started in all these cells.
3.  If **actUacBarringAlarm** is set to true the gNB-DU raises for each cell with overload automatic UAC trigger configured the new fault EFaultId_AutomaticUnifiedAccessControlBarringAl indicating that automatic UAC is started.

### 4.3 Postconditions

-   All cells under overloaded gNB-DU broadcast the maximum configuration of automatic UAC parameters in SIB1 for all cells with overload automatic UAC trigger configured.
-   If actUacBarringAlarm is set to true new fault EFaultId_AutomaticUnifiedAccessControlBarringAl indicating that automatic UAC is started is Raised for these cells.
-   UE follows the AC Barring information received in SIB1 and may be barred to access NR serving cell when trying to access the network.
-   check if alarm on cells withot profile with actUacBarringAlarm set to false is not rised
